## 1. Executive Summary

Operation Ironclad was launched to recover and authenticate host-execution evidence from the 10-case acceptance cohort reported under commit `4cc6c638`. The previous operator report claimed **9 PASS / 1 BLOCKED** with a **10/10 route match** against an asserted "frozen oracle".

An exhaustive forensic recovery of the local Antigravity host environment (`~/.gemini/antigravity/brain/`), combined with an independent audit of the test runner, traces, fixtures, and Git logs, establishes that:
1. **No authentic host subagents were dispatched:** The 10 cases were generated sequentially within a single operator session (`b3772c92-61af-4afa-b3ba-da7137c94ff1`) via an inline runner script (`execute_cohort.mjs`). `invoke_subagent` was called **0 times**.
2. **Event IDs and session IDs are synthetic summaries:** Identifiers such as `antigravity-acceptance-20261026-case01` and `ev-case-01-001` were programmatically constructed in Node.js memory. No links exist to authentic Antigravity host tool-call IDs or unmodified host tool results.
3. **Oracle was not frozen or blind:** `frozen-oracle.json` was authored by the operator in the same session at `16:12:04Z`. Four minutes later, `execute_cohort.mjs` loaded `frozen-oracle.json` and directly assigned `let observedRoute = caseSpec.expectedRoute`. The claimed "100% route accuracy" was a programmatic echo, not an autonomous routing discovery.
4. **State changes on disk are intact but self-reported:** Physical inspection of the `/tmp/brad-cohort-fixtures/case-09` (refusal) and `case-10` (blocked) directories confirms clean working trees, zero commits, and zero remotes. However, because the test script executed in-process without an external observer daemon, before/after JSON snapshot equality alone does not prove external immutability.
5. **Multi-dimensional re-scoring:** When evaluated across 6 strict dimensions (Structural, Host Origin, Route Semantic Accuracy, Workflow Execution, Task Completion, Independent Outcome), the cohort authentic score is:
   - **Authenticated Native Host PASS:** **0 / 10**
   - **Authentically BLOCKED:** **1 / 10** (Case 10: missing specialist confirmed)
   - **REVIEW_REQUIRED (Simulation Verified, Host Unverified):** **9 / 10** (Cases 01–09)

## 3. Oracle Chronology & Integrity Analysis

The previous scorecard asserted `oracleIntegrityVerified: true` based on matching `oracleSha256` (`c5af79d1...`) against `manifestOracleSha256` (`c5af79d1...`).

### Chronology Findings
1. **Creation within same session:** `frozen-oracle.json` was authored inside session `b3772c92` at `16:12:04Z`.
2. **Clock Discrepancy:** The metadata in `frozen-oracle.json` asserted `"frozenTimestamp": "2026-10-26T21:42:00Z"`. In local time (IST, UTC+5:30), 21:42:00 IST is 16:12:00 UTC. The operator accidentally appended `Z` (UTC) to a local timestamp, dating the oracle 5.5 hours into the future.
3. **Execution Coupling:** `execute_cohort.mjs` imported `frozen-oracle.json` directly from the scratch directory.
4. **Conclusion:** The oracle was neither externally frozen nor hidden from the test harness. Any claim of independent route discovery or 100% blind routing accuracy is **INVALIDATED**.

## 5. Validation Pipeline Architecture (6 Dimensions)

To eliminate score conflation, the validation pipeline has been upgraded into a 6-dimensional evaluator (`validation/multidimensional-verifier.mjs`):

| Dimension | Scope | Evaluation Criterion |
|---|---|---|
| **1. Structural** | Data Integrity | Schema compliance, valid SHA-256 digests, safe paths, snapshot structure. |
| **2. Host Origin** | Provenance | Attributable Antigravity session ID, raw transcript SHA-256, genuine tool-call IDs. |
| **3. Route Accuracy** | Semantic Intent | Prompt intent semantically maps to expected route, independent of self-generated oracles. |
| **4. Workflow Execution** | Runtime Engine | Active BMAD workflow engine invocation vs inline scripted simulation. |
| **5. Task Completion** | Deliverable State | Real test exit code 0, generated artifacts, or zero-mutation invariance on refusals. |
| **6. Independent Outcome** | Final Scoring | Fail-closed disposition: PASS only when Dimensions 1–5 succeed; else REVIEW_REQUIRED / BLOCKED / FAIL. |
